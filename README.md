# Worms 2D: Console Artillery

Консольна артилерійська покрокова дуель для двох гравців із процедурною генерацією рельєфу та балістичною симуляцією польоту снарядів з урахуванням сили вітру.

## Запуск гри

З кореня репозиторію:

```
python -m game
```

Клавіші спрацьовують одразу, без Enter (`msvcrt` на Windows). Поле перемальовується ANSI-послідовностями без очищення екрана, тому не мерехтить.

## Керування

| Клавіша | Дія |
|---|---|
| A / D або ← / → | рух вліво / вправо (черв'як залазить на сходинку в 1 клітинку) |
| F | постріл: ввести кут і силу (від 1.5 до 4.5) |
| S | зберегти гру в `savegame.json` |
| Q | здатися |

Клавіші працюють в англійській розкладці. Хід у стіну чи невідома клавіша не забирають хід.

## Меню на старті

- `1`, `2`, ... — рівні з каталогу `levels/levels.json`
- `T` — тестова карта з бетонною стіною (має бути відхилена перевіркою)
- `R` — випадкова процедурна карта
- `L` — продовжити збережену гру (з'являється, якщо є `savegame.json`)
- `Q` — вихід

Після перемоги на рівні з каталогу гра пропонує перейти до наступного.

## Архітектура

Рушій гри не містить жодного `print()` чи `input()`: він лише змінює стан і повертає результати (`MoveResult`, `ShotResult`). Усе виведення робить `ConsoleRenderer`, тому до того ж рушія можна підключити інший інтерфейс.

| Модуль | Що в ньому |
|---|---|
| `game/tiles.py` | `Tile` і нащадки `Air`, `Dirt`, `Concrete` з методами колізії `is_passable`, `stops_shot`, `on_explosion` |
| `game/entities.py` | `Entity` і нащадки `Worm` (гравець, HP), `Projectile` (снаряд з фізикою польоту) |
| `game/field.py` | `Field` — сітка клітинок: межі, гравітація, вибух, `get_neighbors` |
| `game/engine.py` | `Game` — рушій: черга ходів, вітер, рух, постріл, перемога, серіалізація стану |
| `game/levels.py` | завантаження рівнів, BFS-перевірка досяжності, генерація рельєфу, каталог |
| `game/storage.py` | збереження гри в JSON, рекорди в `scores.txt` |
| `game/exceptions.py` | `GameException`, `InvalidMoveError`, `LevelFormatError`, `SaveFormatError` |
| `game/console.py` | `ConsoleRenderer` (виведення) і функції вводу `read_key`, `read_number` |
| `game/app.py` | `ConsoleApp` — з'єднує ввід, рушій і рендерер |

## Клітинки поля

| Символ | Що це | Прохідна | Руйнується |
|---|---|---|---|
| `.` | повітря | так | ні |
| `#` | земля | ні | так |
| `X` | бетон | ні | ні |
| `1`, `2` | гравці | ні | ні |

## Формат файлу рівня

```
name: Два пагорби
spawn1: 4
spawn2: 45
---
..................................................
.........###..........................###.........
XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
```

Спочатку заголовок `ключ: значення`, після `---` іде карта. Усі рядки карти мають бути однакової довжини, `spawn1` і `spawn2` задають x-координати появи гравців.

Каталог рівнів `levels/levels.json`:

```json
{
  "levels": [
    {"file": "level1.txt", "title": "Два пагорби"},
    {"file": "level2.txt", "title": "Каньйон з навісом"}
  ]
}
```

## Перевірка рівня

Після завантаження карта перевіряється:

- рядки однакової довжини, немає невідомих символів, є `spawn1` і `spawn2`;
- гравець не з'являється всередині землі і не падає за карту;
- між гравцями є шлях через повітря (BFS). Якщо гравців розділяє непробивна стіна, рівень відхиляється.

Випадкова карта генерується повторно, поки не пройде цю перевірку.

## Файли, які створює гра

- `scores.txt` — рекорди, топ-5 найшвидших перемог показується після кожної гри
- `savegame.json` — збережена гра (поле, позиції, HP, номер ходу)
